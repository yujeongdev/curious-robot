## Problem Statement

The existing application proves the physics-discovery loop, but the experience is split across terminal logs, a Newton recording, JSON, plots, and a generated HTML report. `curious-robot run` is headless apart from CLI messages. `curious-robot-replay --visual` prints the command for Newton's replay viewer rather than opening a unified experience.

Build an Agent Lab where a viewer can watch the Franka, see the active discovery stage, inspect the exact evidence behind each decision, scrub the same run afterward, and export the whole synchronized experience as an MP4. The UI must make agentic physics discovery legible without pretending to expose private chain-of-thought.

## What Makes This Cool

The core moment is not a chat response. It is the instant a physical measurement changes the robot's belief and therefore changes what it does next. The UI synchronizes four views of that moment:

1. the Newton frame;
2. the active stage in the discovery loop;
3. the measured force, motion, and uncertainty change;
4. the agent's concise, inspectable rationale and selected tool.

Live execution and replay use the same ordered event stream and the same frontend reducer. A recorded run therefore replays the simulation, stage progress, evidence feed, and plots together.

## Constraints

- NVIDIA Newton and MuJoCo Warp remain the physics owners. The web app must not reproduce or alter physics.
- Deterministic controllers, not the browser or an LLM, own physics timesteps.
- Hidden truth parameters must never enter the live agent-facing event stream. Evaluator comparisons appear only after a terminal state in local evaluator mode and are clearly labeled.
- Expose structured rationale, tool calls, measurements, belief deltas, predictions, and verification. Never claim to expose raw chain-of-thought.
- The first version runs locally on the GPU workstation. Remote multi-user deployment is not required.
- Keep the Python research package installable and the existing CLI usable without the web frontend.
- Use `uv run` for Python commands and `pnpm` for the TypeScript workspace.
- Use React, TypeScript, Vite, Tailwind CSS, and shadcn/ui. Next.js server features are unnecessary for a local Python-owned runtime.
- The approved wireframe is `docs/designs/agent-lab-wireframe.png` with editable source in the adjacent HTML file.

## Premises

1. The product is a physics evidence workspace, not a chat-first demo.
2. The frontend consumes an ordered, typed event stream and never queries mutable simulator internals directly.
3. A single event model must drive both live execution and replay.
4. The central viewport is an R3F presentation mirror driven only by Newton-emitted visual frames. It contains no browser physics, collision, interpolation authority, or parameter estimation.
5. Surface and cube friction are not independently identifiable from one pairwise interaction. The agent estimates effective cube–surface static and dynamic friction.
6. MP4 generation records the complete browser composition, not only the Newton viewport.
7. The generated MP4 and GIF are portfolio artifacts; large binaries are produced by a script and may be attached to a GitHub Release rather than committed on every run.

## 2026 Interaction Direction

The UI follows current agent-application patterns without copying a generic chatbot:

- stream lifecycle, tool, state snapshot/delta, activity, and custom domain events;
- render tool calls as inspectable cards with typed arguments and results;
- show durable run state, pause, resume, cancel, replay, and explicit failures;
- use progressive disclosure for dense measurements;
- reserve approval UI for actions that actually need human authority;
- make observability first-class through timestamps, duration, sequence, and provenance;
- use generative components only for domain evidence, never arbitrary unvalidated UI code.

## Visual Direction: Precision Lab Instrument

The interface should feel like a calibrated robotics instrument, not a SaaS dashboard or game HUD. Newton motion is the single visual anchor. Typography, spacing, signal color, and precise state changes provide hierarchy; decorative glow, gradients, large shadows, and repeated rounded cards are prohibited.

Before implementation, run `/design-consultation` and create repository-level `DESIGN.md` using this section as the approved direction. `DESIGN.md` must resolve exact OKLCH values, bundled font files/licensing, light/dark policy, chart palette, R3F overlay encodings, shadcn variants, density, focus styles, and deterministic recording motion. Agent Lab implementation cannot begin past Slice 0 until that file exists and this plan's semantic roles map to its tokens.

### Typography

- Primary UI and Korean text: bundled `IBM Plex Sans KR`, 16 px minimum body size, 1.45–1.6 line height.
- Measurements, event IDs, timestamps, SI units, and code-like values: bundled `IBM Plex Mono` with tabular numerals.
- One display scale only: 20 px workspace title, 16 px region title, 14–16 px metadata according to contrast and density. Never reduce essential status or evidence below 14 px.
- Fonts ship locally under their licenses so offline demos and MP4 capture do not depend on network loading.

### Color roles

Define semantic CSS variables in OKLCH, with tested light and dark values:

- `--canvas`: near-black graphite live workspace;
- `--surface-1` and `--surface-2`: calm neutral elevation through value difference, not shadows;
- `--text-primary`, `--text-secondary`, `--text-muted`: body contrast ≥4.5:1;
- `--signal`: cyan used only for current phase, selected evidence, synchronized cursor, and primary Run action;
- `--warning`: amber for degraded/partial states;
- `--danger`: red for safety/terminal failure;
- `--success`: restrained green for verified predicates, never the only success indicator;
- `--truth-reveal`: evaluator-only color paired with an explicit label and icon.

Force vectors, predicted paths, observed paths, and target regions have separate color-plus-shape encodings so color-blind users can distinguish them. No purple/indigo AI gradient is permitted.

### Geometry and spacing

- 4 px base spacing scale; common gaps 8, 12, 16, 24 px.
- Hairline separators organize full-height regions. Cards exist only for discrete evidence/tool events.
- Radius scale is 2/4/6 px; no uniformly bubbly 12–24 px surfaces.
- Shadows are reserved for transient overlays, menus, and dialogs, not permanent layout regions.
- The R3F viewport remains edge-to-edge within its region; do not inset it inside a decorative card.

### Motion

- Active macro phase uses a restrained 1.5 s status pulse plus text/shape change; respect `prefers-reduced-motion`.
- Evidence events enter once with 120–180 ms opacity/translation and never animate continuously.
- Belief delta animates prior → posterior only when the event becomes current; replay seeking renders the target state immediately.
- R3F camera motion is user-driven or tied to an explicit camera preset, never ambient orbit.
- Recording mode disables nondeterministic UI animation and uses the fixed replay clock.

### Zustand ownership boundary

Zustand hosts the pure `RunState` reducer output and ephemeral viewport state. High-frequency body transforms are written to a preallocated frame buffer and applied to R3F object refs on demand; they do not trigger a React tree rerender per body per frame. TanStack Query owns request/response server state. This separation prevents two caches from competing for the same run state.

### shadcn component allowlist

Use only `Button`, `Badge`, `Select`, `Tooltip`, `ScrollArea`, `Card`, `Collapsible`, `Separator`, `Sheet`, `AlertDialog`, `Progress`, `ToggleGroup`, and `ResizablePanelGroup` in the first slice. `Tabs` is reserved for Live / Replay, not the discovery stage machine. Each component needs keyboard, focus, loading, disabled, and error-state tests. Avoid carousel, command palette, data table, calendar, form builders, and decorative components until a user flow requires them.

## Approaches Considered

### Approach A: Sidecar Dashboard

Forward existing log strings through SSE and place a Newton viewer beside them. This ships fastest but creates separate live and replay paths and cannot reliably correlate evidence with a specific physics frame.

### Approach B: Event-Sourced Agent Lab — Selected

Refactor run orchestration to emit immutable typed events. Store them append-only, stream them live, and replay them through the same reducer. This requires an explicit event contract but solves live UX, replay, MP4, debugging, and research provenance together.

### Approach C: Browser-Native Physics Twin

Run a second browser physics model in Three.js/Rapier. This was rejected because it could diverge from Newton. The selected R3F viewport is only a presentation mirror and does not implement this rejected approach.

## Recommended Architecture

### Engineering scope decision

The plan exceeds eight files and introduces more than two services, but reduction to a sidecar dashboard would violate the approved live/replay/event-provenance goal. Proceed with the full architecture in dependency-ordered vertical slices, not one big-bang branch. Complexity is accepted only at these essential boundaries: scientific core, event durability, worker lifecycle, local API, frontend reducer, R3F mirror, and media capture.

Scope is reduced where it does not block the core: start with one randomized surface family before expanding profiles; preserve reduced belief worlds rather than adding Franka to every candidate; use a complete latest frame inside the existing snapshot rather than a second frame API; defer chat, Compare, remote scheduling, authentication, abandoned-run resume, Monaco, and table tooling.

```text
React/Vite/shadcn Agent Lab
  ├─ StageStepper
  ├─ NewtonViewport (R3F v9 presentation mirror)
  ├─ EvidenceFeed
  ├─ TelemetryDock
  └─ RunControls / ReplayScrubber
             │ HTTP commands + SSE events
             ▼
FastAPI control plane
  ├─ RunManager: one active GPU run
  ├─ EventBroker: ordered fan-out and reconnect
  ├─ EventStore: artifacts/<run_id>/events.ndjson
  ├─ Artifact API: manifests, plots, recordings, video
  └─ NewtonWorker: existing Python runner in a dedicated subprocess
             │ AgentEventSink
             ▼
Curious Robot domain
  ├─ truth environment
  ├─ typed tools
  ├─ experiment planner / SysID
  ├─ belief environment
  └─ deterministic action controllers
```

### Viewer decision

Use React Three Fiber v9 with Three.js and selected Drei helpers as the integrated viewport. R3F v9 is paired with React 19. It renders only authoritative Newton visual frames containing link/body transforms, visual asset IDs, contacts, forces, targets, and prediction overlays. `@react-three/rapier`, Cannon, or any browser physics package is forbidden.

The official Newton ViewerFile/Rerun output remains the scientific reference and independent visual diagnostic. A parity test compares sampled R3F world transforms against recorded Newton state. The browser may interpolate cosmetically between published display frames during live viewing, but replay/capture disables interpolation and renders exact frames with `frameloop="demand"`.

Franka assets are resolved in a spike: prefer build-time URDF-to-GLB conversion with a link manifest preserving stable link names and local visual transforms. Do not add a runtime URDF loader until the spike proves conversion loses required information. A manifest maps stable Newton body labels to GLB nodes; a missing or mismatched link fails the viewport rather than silently rendering a partial robot.

### Process boundary

The FastAPI process owns the run manager. Newton execution runs in one dedicated **subprocess**, not a thread, because GPU context, viewer lifecycle, pause/step control, crash detection, and cancellation must not block or corrupt the async HTTP loop. The worker owns Warp/Newton initialization and exits after final artifact flush. The manager detects EOF/process death, marks the run failed, and preserves committed events. Cooperative cancellation gets 5 seconds before SIGTERM and another 5 seconds before SIGKILL. Linux workers set a parent-death signal, hold an exclusive device lock containing PID/run ID, and emit a heartbeat. On server restart, reconciliation checks the lock/PID before releasing the GPU slot: a live orphan is terminated and awaited; a dead orphan is cleaned up; its non-terminal run receives `run.abandoned`. No new run starts until reconciliation completes. Abandoned runs may be inspected but not resumed. MVP supports one active run plus terminal replay metadata. Starting a second run returns HTTP 409 with the active `run_id`.

### Transport

- `POST /api/runs`: create a run with seed, device, material randomization bounds, and recording options.
- `GET /api/runs/{run_id}`: current snapshot and artifact links.
- `GET /api/runs/{run_id}/events?after_sequence=N`: SSE stream with explicit cursor and `Last-Event-ID` reconnect; storage catch-up completes before live fan-out.
- `POST /api/runs/{run_id}/pause|resume|step|cancel`: bounded run controls.
- `POST /api/runs/{run_id}/reset`: create a new run from the same configuration; never mutate or erase the original run.
- `GET /api/runs/{run_id}/events.ndjson`: terminal runs only; terminal means completed, failed, cancelled, or abandoned. Active runs use SSE or a snapshot bounded by a sequence watermark.
- `GET /api/runs?status=completed`: stored-run picker metadata sorted by creation time.
- `GET /api/runs/{run_id}/artifacts/{name}`: safe allowlisted artifact access.

SSE is enough because the server produces most updates and browser commands are ordinary HTTP requests. Do not introduce WebSocket complexity until bidirectional high-rate interaction is measured as necessary. An event is persisted and flush-confirmed before publication. `GET /api/runs/{id}` returns an atomic snapshot containing `snapshot_sequence`; the client subscribes with `after_sequence=snapshot_sequence`, the server replays later stored events, then atomically joins live fan-out. `Last-Event-ID` is equivalent on reconnect. An expired or unknown cursor returns HTTP 409 with `snapshot_required=true`. Each subscriber queue is bounded by both 2,048 events and 16 MiB; one event is capped at 512 KiB and contacts/overlays are deterministically truncated with explicit counts. Overflow disconnects only that subscriber with its last delivered sequence, never persistence, controls, or healthy subscribers. Authoritative 240 Hz measurements stay in the measurement artifact, while UI sample events are capped at 30 Hz and charts decimate to at most 2,000 visible points.

### Single-writer and IPC contract

The FastAPI manager process is the only authority that validates public payloads, assigns `sequence`, appends events/indexes, advances the snapshot reducer, and publishes SSE. The spawned Newton worker sends unsequenced typed event intents over a dedicated `multiprocessing.Pipe` using `send_bytes`; commands use a second pipe. Do not use `multiprocessing.Queue`, whose feeder thread and abrupt termination can corrupt buffered messages. The worker uses the `spawn` start method so CUDA/Warp state is never inherited through `fork`.

For each accepted intent the manager performs: validate and redact → assign sequence → serialize once → append complete newline and flush Python buffers → update index/reducer → publish those exact bytes. `fsync` occurs at stage boundaries and terminalization, not at 30 Hz, so process-crash durability is guaranteed for flushed records and machine-power-loss durability for the last fsynced boundary. Disk/serialization failure enters out-of-band manager error state, stops physics at the next control checkpoint, rejects new run commands, preserves the committed prefix, and does not assume it can append `run.failed` to the failed store.

Terminalization drains already accepted worker messages, closes worker input, commits artifact metadata, appends exactly one of `run.completed|failed|cancelled|abandoned`, fsyncs, freezes terminal downloads, and rejects late worker intents. Terminal NDJSON never changes after it becomes downloadable.

Snapshot creation and SSE registration share the event-store lock. A snapshot embeds the complete latest allowed visual frame for each active `(world_instance_id, scenario_id)` so a client connecting to a paused run renders immediately even if no later event arrives.

```text
Browser commands ─HTTP─> FastAPI RunManager ─command Pipe─> Spawned Newton worker
                              │                              │
                              │                    ControlGate.before_step()
                              │                              │
                              │<──── unsequenced event-intent Pipe ─────┘
                              ▼
                 validate/redact → assign sequence
                              ▼
                     append exact NDJSON line
                              ▼
                 index + reducer + atomic snapshot
                              ▼
                    identical committed SSE bytes
                              ▼
             Browser reducer → R3F/evidence/telemetry
```

`runner.py` and `tools.py` depend only on a small `AgentEventSink` protocol with a no-op/CLI implementation; they never import FastAPI or frontend concerns. CLI dispatch imports simulation code lazily only for physics commands, so web fixture/replay tooling can start without initializing Warp.

### Local API security

- Bind to `127.0.0.1` by default; non-loopback requires an explicit unsafe-development flag and warning.
- Validate `Host`, require same-origin `Origin` for mutating requests, reject wildcard CORS, and accept JSON content types only.
- Use an unpredictable per-launch local control token in mutation headers and the bootstrapped page; never place it in URLs or logs.
- Never mount an artifacts directory as static files. Artifact routes resolve an allowlisted artifact ID and enforce public/evaluator classification.
- Public artifacts include sanitized events, measurements, visual frames, prediction/observation plots, and public replay. Evaluator artifacts include `reexecution.json`, truth comparison plots/GIF/HTML, evaluator reveal, and unaudited Newton ViewerFile model data. Evaluator artifacts are served only after a terminal state with evaluator mode enabled.

### Run control semantics

- `pause` in `running` returns a command acknowledgment with `pause_pending`; eventual `run.paused` confirms state. Repeating pause in `pause_pending` or `paused` succeeds idempotently without another lifecycle event.
- `resume` in `paused` returns `resume_pending`; eventual `run.resumed` confirms state before the next physics advance. Repeating resume in `resume_pending` or `running` succeeds idempotently without another lifecycle event.
- `step` is accepted only in `paused` and advances one display frame: eight 240 Hz physics substeps for the canonical 30 Hz display cadence. It emits one acknowledged visual frame and remains paused. ViewerFile stride four remains an independent diagnostic recording cadence.
- `cancel` is valid during initialization, running, or paused. It requests cooperative shutdown, writes a terminal event, saves partial artifacts, and escalates only after the documented deadlines.
- Commands after a terminal state return HTTP 409. Commands received during an atomic controller segment take effect at its next safe boundary.
- `safe stop` is the UI label for cancel-with-artifact-preservation. `reset` starts a new immutable run with the same settings.

All environment/controller loops call one injected `ControlGate.before_step()` at the shared `NewtonWorld.step()` boundary, including settle, joint motion, weighing, probes, push, pick-place, and belief candidate worlds. The gate checks pause/step/cancel without taking a sensor observation or advancing RNG state. Initialization and SciPy optimization expose explicit cancellation checkpoints. Maximum cooperative cancellation latency is one display frame during stepping and 250 ms during host-side optimization/asset work; escalation deadlines remain the documented 5 s/5 s sequence.

## Event Contract

Add a discriminated Pydantic union and generate matching TypeScript types. Every event contains:

```text
event_id: UUID
run_id: UUID
sequence: monotonically increasing integer
wall_time: RFC 3339 timestamp
sim_time_s: float | null
stage: discovery stage
frame_id: integer | null
type: discriminator
payload: typed body
schema_version: SemVer string
iteration_id: integer
stage_instance_id: UUID
```

IDs and payload rules:

- `tool_call_id` links tool start/completion/failure; `evidence_id` links measurements, estimates, and rationale citations; `belief_revision` is monotonic.
- Positions are world-frame meters, velocities are world-frame m/s, force is Newtons with an explicit producer and frame, torque is N·m, and angles are radians.
- Uncertainty uses standard deviation plus an ordered 95% interval and physical bounds; censored friction estimates state which bound is open.
- Unknown event types from a newer major schema stop replay with an upgrade message. Unknown optional fields within the same major version are ignored and retained when reserialized.
- `stage.completed` includes outcome, duration, evidence IDs, and an explicit `skipped_reason` or `failure_reason` when applicable.

Required event types:

- `run.started`, `run.paused`, `run.resumed`, `run.completed`, `run.failed`, `run.cancelled`, `run.abandoned`
- `stage.entered`, `stage.completed`
- `rationale.published`
- `tool.started`, `tool.completed`, `tool.failed`
- `measurement.sampled`, `measurement.summary`
- `belief.updated`
- `simulation.belief_rebuilt`
- `simulation.visual_frame`
- `prediction.completed`
- `action.selected`, `action.executed`
- `verification.completed`
- `learning.completed`
- `safety.triggered`
- `evaluation.revealed`
- `reexecution.completed`
- `artifact.created`

`rationale.published` contains a short decision summary, cited evidence IDs, alternatives considered, and why the selected option won. It never contains hidden chain-of-thought.

`belief.updated` contains prior and posterior means, uncertainty intervals, evidence IDs, method, assumptions, and model mismatch notes. The UI renders it as a first-class delta card.

`safety.triggered` records the measured condition, limit, controller response, and whether the run can continue. `evaluation.revealed` is legal only after a terminal run state and only in evaluator mode. `reexecution.completed` records environment fingerprints, tolerances, maximum/RMS errors, sample count, and pass/fail.

### Minimum payload schemas

| Event | Required payload |
| --- | --- |
| `run.*` | state, reason, configuration commitment, worker PID when applicable |
| `stage.*` | stage instance ID, iteration, prior/next stage, outcome, evidence IDs, duration/reason |
| `rationale.published` | summary, evidence IDs, considered option IDs, selected option ID |
| `tool.*` | tool call ID, tool name, validated public arguments, duration, public result/error |
| `measurement.sampled` | evidence ID, sensor kind/producer, frame, SI units, values, validity |
| `measurement.summary` | evidence ID, accepted/rejected counts, aggregate values, quality flags |
| `belief.updated` | revision, parameter name, prior/posterior, uncertainty, method, evidence IDs, mismatch notes |
| `prediction.completed` | action/scenario IDs, final pose, target error, success probability, force/tip metrics, feasible/reasons |
| `action.selected` | selected action ID, candidate score summaries, rationale event ID |
| `action.executed` | action ID, controller result, observed terminal state, safety events |
| `verification.completed` | success, goal predicates, prediction residual, tolerance |
| `learning.completed` | affected parameters, old/new uncertainty, residual evidence, follow-up decision |
| `artifact.created` | artifact ID, allowlisted kind, relative path, media type, bytes, SHA-256 |
| `snapshot` | snapshot sequence, reducer schema, run/stage instances, belief, artifact index, and complete latest public visual frame for every active scene/scenario |

### Visual-frame contract

`simulation.visual_frame` is a versioned display event, not a physics state replacement. Its payload contains:

```text
frame_id: monotonic integer
source_state_sequence: event sequence that produced the frame
scene: truth | belief
world_instance_id: UUID
scenario_id/action_id: optional stable identifiers
belief_revision: integer | null
body_manifest_id: identifies the valid body/link set for this world
sim_time_s: float
presentation_time_s: monotonic run-level replay/capture time
bodies: [{body_id, label, asset_node_id, position_m[3], orientation_xyzw[4]}]
contacts: [{position_m[3], normal_world[3], force_world_n[3], shape labels}]
vectors: force/target/prediction overlays with frame and SI units
target_region and camera_hint
```

Stable `body_id` and `asset_node_id` values come from the body manifest for that world instance, never array order guessed by the browser. Reduced belief rollouts intentionally use a different manifest than the full truth world. `scenario_id` distinguishes push/pick candidates; each world keeps its own physical time while `presentation_time_s` provides one run-level timeline. Live transport uses the same ordered SSE channel at ≤30 Hz. The complete `simulation.visual_frame` event, including transforms and overlays, is first appended as one newline-delimited record to the canonical uncompressed `events.ndjson`, then the identical committed event is published over SSE. A sidecar index maps `(world_instance_id, frame_id) → event sequence → file byte offset` at line boundaries. Replay seeks directly to the indexed line and renders the same event bytes. On recovery, an incomplete final line is discarded and the index is rebuilt from the last committed newline. Tests seek a late frame without scanning the entire recording and recover all committed frames after a deliberately truncated final line. Public-data allowlisting applies before serialization, including scene identity and labels.

## Discovery Stage Model

Use these display stages, mapping multiple low-level events into a legible product narrative:

1. Observe
2. Reason
3. Identify Unknowns
4. Design Experiment
5. Act
6. Measure
7. System Identification
8. Update Simulation
9. Predict
10. Execute
11. Verify
12. Learn

Each stage has `pending`, `active`, `completed`, `failed`, or `skipped`. Experiments can repeat, so the authoritative model is an ordered list of `stage_instance_id` values grouped by `iteration_id`, not one mutable status per stage name. Legal flow follows the existing runner: Calibrate may transition directly back to Discover for the next probe; after experiments stop, Decide contains Predict and Select Action; Execute contains physical execution, Verify, then Learn. A failed validation may also return to Discover. It cannot jump backward inside an existing stage instance. The top stepper shows aggregate completion and highlights the active instance; an `Experiment 2/3` badge reveals repetition. Clicking a completed aggregate stage opens its instances and seeks to the selected instance's first event. Failure and skipped reasons are always visible.

The top-level stepper uses six macro phases rather than twelve equal-width labels:

| Macro phase | Detailed stages |
| --- | --- |
| Observe | Observe |
| Discover | Reason, Identify Unknowns, Design Experiment |
| Experiment | Act, Measure |
| Calibrate | System Identification, Update Simulation |
| Decide | Predict, Select Action |
| Execute | Execute, Verify, Learn |

The active phase displays the exact substep, target parameter/action, iteration badge, and elapsed time, for example `Experiment · Measure static friction · 2/3 · 01:24`. Selecting a macro phase expands its stage instances and seeks to the chosen instance. The twelve-stage loop remains authoritative in events, replay, accessibility labels, and the detail drawer.

## Surface Material Randomization

Replace the implicit ground plane material with an explicit hidden `SurfaceParameters` owned only by the evaluator/truth scene:

```text
surface_profile_id
effective_static_friction range: 0.20–0.90
effective_dynamic_friction range: 0.10–min(0.60, μ_static-0.03)
restitution range: 0.00–0.15
visual_roughness range: 0.25–0.90
visual_base_color: profile-dependent
optional compliant/contact numerical settings: fixed, not inferred
```

Initial profiles may be named wood, rubber mat, coated metal, and polymer, but names and visuals are presentation metadata. Physics samples remain continuous within bounded ranges. The agent receives only camera/object pose, robot state, and measured force observations.

The belief must say `effective cube–surface friction`. Estimating independent cube and table coefficients is deferred until multiple known reference surfaces or objects provide sufficient excitation.

The UI initially displays `surface: unknown`. After experiments it displays inferred effective parameters and confidence, not the hidden profile. An evaluator-only reveal becomes available after any terminal state (`completed`, `failed`, `cancelled`, or `abandoned`) so failed-run postmortems remain possible.

### Public-data policy

One allowlist governs SSE events, snapshots, request echoes, API errors, logs, artifact metadata, viewer labels, and frontend state. Hidden sampled values, episode-specific hidden bounds, private profile IDs, and direct Newton material arrays are evaluator-only. Run creation echoes only user-supplied public configuration and an opaque `surface_commitment` hash. Evaluator reveal is generated after a terminal event, stored separately, and served only when local evaluator mode is enabled; `evaluation.revealed` follows that same rule for all four terminal states. Tests recursively scan every public channel for forbidden truth field names and seeded values.

## Screen Structure

### First-run journey and emotional arc

The New Run screen has one primary action, `Run discovery demo`, using a versioned known-good preset. `Configure run` is secondary disclosure for seed, GPU, observation noise, surface bounds, and recording options. Opening the page never starts GPU work without an explicit action. `--autorun` remains automation-only and is visibly labeled when active.

| --- | --- | --- | --- |

Time horizons:

- 5 seconds: understand the mission and start the known-good demo.
- 5 minutes: inspect one complete evidence-to-action loop and replay a stage.
- Long term: compare reproducible runs through artifacts and event provenance without relearning the interface.

### Accessibility contract

- All actions are reachable by keyboard with visible focus; shortcuts are disabled while a text/select control owns focus and are listed in a help Sheet.
- Stage changes use a polite live region; `safety.triggered` and terminal failures use an assertive announcement containing the measured condition and response.
- Canvas content has a synchronized DOM summary: active camera, object pose, robot/end-effector state, contacts, vectors, target predicate, and selected frame. Evidence and telemetry remain usable when WebGL is unavailable.
- Touch targets are at least 44×44 px. Body text is at least 16 px and 4.5:1 contrast; large labels are at least 3:1.
- Color is never the sole encoding. Phase state adds icon/text, prediction/observation paths differ by dash/marker, and force/target overlays differ by shape.
- `prefers-reduced-motion` removes pulse/translation and camera transitions. Replay seeking never requires animation to communicate state.
- Resizable separators expose keyboard adjustment and numeric accessible labels. Focus order follows header → phase stepper → viewport controls → evidence → telemetry.
- R3F pointer interactions have equivalent buttons/list controls; essential actions do not depend on hover, drag, or canvas hit testing.

### Design-review auto-decisions

The user delegated remaining design choices to the reviewer; these recommended behaviors are approved without additional gates:

- Evidence Feed follows the newest event only while the user is at the live edge. Scrolling up or selecting a stage enters inspection mode and pins only the selected sequence/frame plus a bounded 500-event local tail; canonical state continues advancing without duplicating the whole run. Evicted history is fetched by indexed range from storage. `N new events · Return to live` reduces the ordered tail to current state. - Precision Lab Instrument dark mode is the canonical live/capture theme. `/design-consultation` must also define an accessible light theme for long replay/review sessions, but theme switching is not permitted to change chart/overlay semantics.
- Evidence cards are chronological and append-only. Final decision and verification are pinned as summaries without reordering the underlying event history.

## Frontend State

The frontend keeps a normalized `RunState` produced by a pure reducer over ordered events. The reducer rejects duplicate event IDs, detects sequence gaps, and requests a snapshot before resuming. It never fabricates a later stage when an event is missing.

The same reducer supports:

- live SSE events;
- replay from `events.ndjson`;
- deterministic frontend tests from event fixtures;
- MP4 capture using a fixed replay clock.

Backward seeking resets the reducer to the closest indexed snapshot at or before the requested sequence and reduces forward to the target. Snapshots are written at stage boundaries and every 500 events. Seeking between measurement samples snaps to the nearest display frame while showing the exact requested simulation time. During live inspection, new events continue buffering; `Return to live` applies the buffered tail and resumes following the newest frame.

## MP4 and GIF Pipeline

Add a deterministic capture command:

```bash
pnpm --dir src/web record:demo --run artifacts/<run_id> --output docs/media/curious-robot-demo.mp4
```

Implementation:

1. launch the web UI in replay mode with a fixed 1280×720 or 1920×1080 viewport;
2. load `events.ndjson` and the Newton visual recording;
3. advance a fixed replay clock rather than wall-clock timers;
4. after each render barrier, capture one numbered PNG/WebP frame from Playwright;
5. encode the explicit image sequence to H.264 MP4 at 30 fps with ffmpeg;
6. derive a short optimized GIF preview;
7. write checksums and source `run_id` beside the video.

Each output video frame waits on a render barrier: the event reducer acknowledges the target sequence, Recharts finishes its animation-free render, and the R3F viewport acknowledges the matching `frame_id`. Capture then writes one numbered image; ffmpeg assigns evenly spaced timestamps at 30 fps. Luminance/edge checks reject blank frames. Staleness uses acknowledged frame IDs and expected-motion intervals, because Observe, Reason, and Pause may legitimately show an unchanged scene. Visual-change assertions apply only to checkpoints that require motion.

The capture script checks for Playwright Chromium and ffmpeg and prints actionable setup instructions if absent. It must not silently produce an empty viewport when WebGL or the Newton viewer fails.

GitHub README behavior:

- embed the small GIF preview;
- link the MP4 or GitHub Release asset because GitHub README does not reliably inline local MP4 video;
- include one screenshot with labels;
- retain CLI and headless usage below the visual quick start.

## Engineering Review Corrections to Existing Scientific Boundaries

These pre-existing paths must be corrected before event/UI work so the Agent Lab does not make a hidden truth leak more visible:

1. `environment.py:271` currently sets public `MotionSample.normal_load_n` from `self._parameters.mass_kg * GRAVITY`. This is a direct hidden-mass read disguised as a measurement. Replace it with an optional measured-normal-load field from a validated contact/virtual sensor producer; when unavailable, the estimator derives assumed normal load from the agent's mass posterior and records that assumption. Add sentinel-value tests across every public tool/event/artifact.
2. `environment.py:409-411` currently adds gravity compensation using hidden truth mass during pick/place. Change the deterministic controller contract to receive `assumed_mass_kg` from the agent belief. Truth and belief environments execute the same command/controller parameters; the truth world uses hidden mass only inside physical dynamics.
3. `tools.py:271-275` returns objects home through `execute_pick_place` without an explicit public assumed mass. Route restoration through the same belief-parameterized controller and record it as an action/tool event.
4. `sysid.py:106` consumes `sample.normal_load_n`; after correction it must distinguish measured normal load from posterior-derived load and propagate uncertainty accordingly.
5. Cross-module calls currently use private members such as `RobotTools._return_object_home`, `NewtonWorld._cube_state`, and `_tool_pose`. Promote explicit observation/controller-boundary methods before adding events; the web/event layer must not deepen those private couplings.

Event emission remains DRY: orchestration owns stage/rationale/decision events, the tool façade owns tool lifecycle and evidence summaries, the environment owns display-frame and safety events, and the run manager owns process/storage/terminal lifecycle. No layer emits another layer's event type.

These are P1 scientific regressions. Tests must fail if the hidden sentinel mass appears numerically in observation/tool/event payloads before evaluator reveal, even under an unrelated key.

## Failure and Safety States

- GPU unavailable or Warp initialization fails;
- asset download/preprocessing in progress or failed;
- visual-frame stream or R3F asset mapping lost while physics continues;
- SSE client reconnect with a sequence gap;
- Newton worker crash;
- force safety stop or controller timeout;
- event store write failure;
- recording/capture dependency missing;
- MP4 viewport blank or WebGL unavailable;
- user closes the browser while a run continues;
- replay schema version incompatible.

The run manager must preserve the event log and partial artifacts on failure. The UI must show whether the physics worker is still running independently of viewer connectivity.

### Engineering failure-mode matrix

| Code path | Realistic failure | Test | Handling | User-visible result |
| --- | --- | --- | --- | --- |
| Worker startup | CUDA/assets hang or child exits before ready | timeout/EOF integration | manager cancels/joins, preserves init log, frees lock only after reconciliation | exact failed initialization step and rerun command |
| Control gate | pause/cancel arrives inside long controller | inject command in every controller category | next `before_step()` boundary acknowledges; host work polls ≤250 ms | pending state then paused/cancelled, never silent |
| Event append | ENOSPC or truncated line | fault-injected filesystem | out-of-band manager error, bounded physics stop, committed prefix retained | storage failure banner and downloadable prefix |
| Snapshot/SSE | append races subscription | barrier-controlled integration | shared lock, storage catch-up, dedupe, then live fan-out | no missing/duplicate evidence |
| Slow subscriber | frame events exceed event/byte queue | soak with delayed consumer | disconnect only slow client with last sequence | disconnected indicator and recoverable reconnect |
| Visual mirror | missing GLB link or stale frame ack | manifest/parity/browser tests | fail viewport layer, keep DOM evidence and physics worker independent | frozen last frame with explicit visual error |
| Artifact access | caller requests evaluator/path traversal asset | actual HTTP response tests | opaque artifact IDs, policy check, no directory mount | 403/404 without leaking path or metadata |
| Replay | corrupt index or incomplete last record | truncated/index mutation tests | rebuild from newline records, discard incomplete suffix | recovery notice with last valid event |
| Capture | render barrier timeout, blank viewport, low disk, ffmpeg missing | browser/capture fault matrix | stop export, preserve completed frames, no false success | exact checkpoint/dependency/disk error and retry command |
| Packaged web | wheel missing fonts/GLB/static build | clean-wheel offline E2E | CLI refuses web startup with build/install guidance | no blank web page |

With these tests and handlers, no listed failure remains silent and there are zero planned critical gaps.

### Interaction-state matrix

| Area | Loading | Empty | Partial / disconnected | Error | Success / terminal |
| --- | --- | --- | --- | --- | --- |
| Run shell | Header says `Preparing Newton` with the current concrete task such as assets, GPU, or worker; Cancel remains available | New Run screen explains the one action: choose preset or custom settings | Persistent amber status names the degraded subsystem while healthy areas remain usable | Red terminal banner names the failed subsystem, preserves run ID, and links partial artifacts | Summary states success/failure predicates, selected action, elapsed time, and Replay CTA |

State rules:

- Never replace existing evidence with a spinner once any committed data exists.
- Never label a run failed because only the browser viewer disconnected.
- Every empty state supplies context and one relevant primary action, not `No data`.
- Partial states state what is still running, what is stale, the last acknowledged sequence/frame, and what the user can safely do.

## Testing Strategy

### Performance budgets and benchmark gate

Slice 0/4 produces a named-workstation baseline with a 10-minute fixture at 30 visual frames/s, normal measurement traffic, and more than 500 evidence cards. Record event bytes/s, serialize/append/flush/publish latency, SSE catch-up, HTTP control latency, seek latency, React commit counts, browser/API/worker RSS, WebGL allocations, GPU readback cost, and capture throughput.

Initial budgets, revised only with committed evidence:

- manager validate→append→publish p95 ≤20 ms for non-frame events and ≤25 ms for visual frames;
- pause/resume/cancel command HTTP p95 ≤50 ms, with state acknowledgment by the next 33.3 ms display boundary during stepping;
- 10,000-event storage catch-up ≤2 s on the named workstation;
- indexed stage/frame seek ≤200 ms when its snapshot/index is warm and ≤750 ms cold;
- no per-body React commits; one R3F invalidation/commit per acknowledged visual frame;
- browser RSS ≤750 MiB for a 10-minute run and growth ≤5% across five replay open/close cycles;
- API manager RSS ≤300 MiB excluding the Newton worker; subscriber queues remain under both event and byte caps;
- event/visual extraction occurs once per eight physics substeps and reuses one host snapshot for bodies, contacts, and overlays;
- capture uses numbered JPEG frames at quality 95, preflights at least 2 GiB free space for a 45-second 1080p export, keeps no unbounded in-memory image list, and deletes temporary frames only after checksum-verified encoding.

Barrier waits have explicit 5-second per-frame timeout with run/frame diagnostics. Capture tests cover missing assets, stale/wrong acknowledgments, WebGL context loss, legitimate still intervals, absent ffmpeg, interrupted export, low disk, and a bright UI surrounding a blank viewport crop.
